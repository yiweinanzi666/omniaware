# node04 显式精度修复方案（待确认，尚未实施）

目标：让正式实验与通过自检的计算精度一致，并防止 BF16/FP32 的校准、答案和决策混用。基准提交为 `28e9514dc432d6891a492390bc4bdef176c519ea`，拟用独立代码分支 `fix/node04-explicit-dtype-20261018`。报告提交不含源码修改。

## 具体改动

1. `src/omniaware/run.py` 增加显式 `--dtype {bfloat16,float32}`，默认仍为 bfloat16；将选择映射为 torch dtype，传给 QwenEAB。新的 node04 自检、S1 和后续获准的 S2 均显式使用 float32。模型 env 实际 dtype 与请求值核对；dtype 随配置保存并参与续跑一致性检查。
2. U 校准与 SeaKR 的 settings 都加入 dtype；两个缓存文件名都加入 dtype 标识，并使用新的本轮缓存根目录。旧目录只读保留，不覆盖、不按文件名直接复制旧校准。编码器相关度/CE 缓存只有在现有指纹严格一致且独立保留来源时才可复用；先以隔离全部缓存为稳妥实现。
3. `scripts/v2_runs.py` 加入并传递同一 dtype 到所有 omniaware.run 命令，包括 calib、dev 和 position-ablation。运行输出、评分、拼表及 decisions 路径使用一致的本轮 namespace（例如 `fp32_20261018`），相关提示命令也指向新目录。保持开发集命令的 `--analysis-eab` 位置要求，校准集不带该标志。
4. 增加针对实际风险的回归测试：dtype 确实传入模型；切换精度拒绝续写同目录；U/SeaKR 指纹和文件名随 dtype 改变；S1/S2 编排全链路使用相同 dtype/namespace；不会覆盖旧答案、旧决策或旧缓存。
5. 冻结阈值、提示词、解析规则、数据切分、候选池、解码预算、评分标准保持原定义。本修复不把 BF16 失败记录改成通过，也不把旧 BF16 S1/S2 与新 FP32 结果合并。

## 实施顺序及通过条件

1. 独立代码分支实施，复核 diff；通过新增定向回归和完整 pytest、pip check，并在干净提交上运行 GPU 自检。
2. 使用真实 8B、正式 FP32 参数运行原版文本＋图片自检；必须退出 0，全部判定项 true，logits ≤ 0.05、attention ≤ 0.02。若失败则保留证据并停下。
3. GPU1 上测量实际 S1 多图样例的峰值显存及耗时；不减图片预算以掩盖 OOM。若 48 GB 不足，停下报告并另提方案。
4. 以新的输出目录和缓存重跑 WebQA/OK-VQA S1，各 50 题；检查空答案、自动格式、前 20 题人工格式、图像输入、日志及环境溯源。如果仍出现整句 short 等人工格式问题，明确报告，不因数值通过自动放行。
5. 只有 S1 全部要求明确通过，才能按原授权进入 S2；S2 完成后停止。S4 仍禁止。

批准范围仅为上述源码实现、精度配置和重新校验。它不包含放宽阈值、改变冻结提示词、修改答案、删除任何既有资产或恢复另一会话的旧 BF16 作业。
