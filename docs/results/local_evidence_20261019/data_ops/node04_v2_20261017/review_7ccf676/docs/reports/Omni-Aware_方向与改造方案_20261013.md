## 0. 一页结论

**方向决策：把论文主线从“如何使用证据（EAB 注意力偏置）”换成“该不该信网页证据、信哪种模态的证据”，也就是逐题在“直接作答 / 文本证据 / 图像证据”之间做有校准的仲裁。EAB 降级为一节机制分析（“注意力被移动了，但答案不动”）。**

理由来自三个可复现的数字：

| 事实 | 数字 | 含义 |
|---|---|---|
| EAB 的天花板 | 只保留有益改写也只有 +2.1%；首 token 领先幅度中位数约 3.4，大于偏置能造成的约 2.0 logit 位移 | 在 EAB 上继续投入，不可能到 5% |
| **direct 与 static 互补** | WebQA 4966 题（去掉 `Sources` bug 后 4180 题）：direct 44.9，static 45.8，**逐题选对上限 58.2（+12.4 分，相对 +27%）**；现有门控只拿到 42.2（全量口径） | 真正的提升空间在“该不该检索”这个决策上 |
| 模态不对称 | 图像题检索有害（43.7→35.4，两路都是完整句时 55.4→46.6），文本题检索有益（46.1→55.5） | “去哪种模态找证据”是真问题，正好对应论文原有的 where 组件 |

**估算**：如果选择器能拿到上限差距（12.4 分）的 40%，就是约 +5 分，相对 static 约 +11%；拿到 25% 也有约 +7%。这比 EAB 已测得的上界（+2.1%）高出一个量级。
**但必须先修 4 个 bug**（第 4 节）：它们会改变 direct 和 static 的绝对分，修完之后要在开发集上重测这个上限差距是否还在。这是整个方案的第一个 go/no-go 判据。

## 1. 我们手里的事实（含今天的新离线实验）

### 1.1 已有结论（详见根因报告）
- **E1 EAB 推不动答案**：512 题上 +0.304 分，其中两题贡献 +0.317，其余 510 题合计 −0.013。在真实 8B 模型的探针中，29/38 题首 token 的领先幅度大于偏置位移。实现本身是对的。
- **E2 U_omni 弱**：u_pre 预测答错的 AUROC 约 0.52（WebQA 512 题）；h_grd 饱和在 0.80–0.96。
- **E3 指标被格式主导**：WebQA 官方 acc_approx 按参考句的关键词召回打分，BART 项又看句子流畅度，回答写成短语还是完整句，影响比方法差异大两个数量级。

### 1.2 今天的新发现
- **N1 `Sources: none` 提示词 bug【已证实】**：WebQA 全量各臂有 433–551 题（约 10%）的原始输出**只有** `Sources: none` 一行，答案为空，acc 约 4–6。根源是带引用格式的系统提示（例如 `mmqa_full2441_execution/protocol.py:12-15`），它写着“没有证据支持就写 `Sources: none`”，模型据此变相弃权；不给证据的 direct 臂受影响最大。这个 bug 让每个臂都白丢约 4–5 个 acc 分，还污染了所有臂之间的比较。
- **N2 臂之间格式不一致【已证实】**：同一提示词下，图像题带检索时答案中位数是 2 个词（`Wood`、`Guitar`），不带检索时是 9 个词的完整句。WebQA 4966 题中，direct 的完整句 acc 51.6，短答 33.2；static 的完整句 51.3，短答 42.5。**格式是各臂之间最大的混杂因素。**
- **N3 OK-VQA 的 static 被冗长答案拖垮【已证实】**：A100 上 256 题开发集，direct 61.5，static 36.3。检索后模型答 `kentucky derby`、`in a bakery`、`pickup truck`，按 VQA 精确匹配全部判错。
- **N4 互补性很大【已证实】**：

  | 数据 | direct | static | 逐题选对上限 | 现有方法 |
  |---|---:|---:|---:|---:|
  | WebQA 4966（acc_approx，全量） | 40.6 | 41.4 | 54.0 | trigger-static 42.2 / trigger-eab 42.2 |
  | WebQA 4180（去掉 Sources bug） | 44.9 | 45.8 | 58.2 | — |
  | ├ 图像题 2021 | **43.7** | 35.4 | 51.2 | — |
  | └ 文本题 2159 | 46.1 | **55.5** | 64.7 | — |
  | OK-VQA dev256（VQA acc） | **61.5** | 36.3 | 64.4 | gated 48.1 |

- **N5 模态不对称在格式对齐后依然存在【已证实】**：两路都输出完整句的题里，图像题 direct 55.4 对 static 46.6（482 题），文本题 46.8 对 56.7（591 题）。**图像证据让图像题变差，这非常反常**，必须排查图像证据管线：分辨率预算、图片是否读对、gold 图是否在上下文里。这可能是第五个 bug（见 P0-5）。
- **N6 已经有比 U 更好的信号【已证实】**：

  | 信号 | 数据 | 预测“直接作答会错”的 AUROC | 预测“检索更好”的 AUROC |
  |---|---|---:|---:|
  | h_sem_pre（不检索时的预测熵） | OK-VQA | **0.708** | 0.537 |
  | u_pre（现有 U） | OK-VQA | 0.593 | 0.516 |
  | u_initial（现有 U） | WebQA 4180 | 0.585 | 0.611 |
  | 两路答案一致度（token F1） | WebQA 文本题 | **0.677** | — |
  | 两路答案一致度 | WebQA 图像题 | 0.478 | — |

  “不检索时模型有多确定”和“两路答案是否一致”，都是零训练、几乎零成本的信号，而且已经比 U 强。

## 2. 方向决策：三个候选的比较

| | A. 校准仲裁（推荐） | B. 修好 EAB 继续做 | C. 纯分析 / 评测论文 |
|---|---|---|---|
| 核心主张 | 逐题决定“信参数知识 / 信文本证据 / 信图像证据”，阈值经过校准，并保证不差于最强单臂 | EAB 提升证据利用 | 揭示多模态 RAG 的评测被格式和指标伪影主导 |
| 提升空间 | 上限 +12.4 分（WebQA），+2.9 分（OK-VQA，修好 static 前） | 已测上界 +2.1% | 不需要提升 |
| 达到 5% 的概率 | 中到高（取决于修 bug 后上限差距还剩多少） | 几乎为 0 | 不适用 |
| 和现有论文的连续性 | 高：保留 whether + where，替换 how | 最高 | 低 |
| 新颖性风险 | 自适应检索已有很多工作（Self-RAG、FLARE、DRAGIN、SeaKR、Adaptive-RAG 等），需要靠多模态不对称的度量、校准保证和机制分析来区分 | — | WWW 主会接受分析类论文的门槛更高 |
| 审稿风险 | 中：需要强基线和校准细节 | 高：结果为零 | 中到高 |

**决策：选 A，并把 C 的发现写进论文。**格式伪影、模态不对称和 EAB 机制分析这三条，不论 A 的最终提升有多大都成立，可以作为论文的“度量与发现”部分。万一 A 的提升不足 5%，论文可以平滑地转成“发现 + 校准方法 + 保证不变差”的定位，不需要从头重写。

## 3. 新方法设计（Omni-Aware v2）

### 3.1 问题形式化
对每个问题 q，在动作集合 𝒜 = {Direct, Text-RAG, Image-RAG, Mixed-RAG} 中选一个动作 a，使期望正确率最大。约束是：在校准集上，相对最强单一动作出现退化的概率不超过 δ。

### 3.2 信号（每题只需 1 次不带证据的 prefill + 少量短解码）
| 信号 | 计算方式 | 已有证据 |
|---|---|---|
| s1 不检索时的置信度 | direct 首 token 的熵 / margin，以及贪心答案的序列 log-prob | h_sem_pre AUROC 0.708 |
| s2 带证据时的置信度 | 各证据条件下首 token 的熵 / margin | 待测 |
| s3 跨条件一致度 | direct 答案与各证据条件答案的 token F1 | 文本题 AUROC 0.677 |
| s4 证据引起的变化 | p(·\|证据) 与 p(·\|无证据) 在首 token 上的 KL 散度 | 待测 |
| s5 检索器信号 | top-1 分数、top-1 与 top-2 之差（按模态分别算） | 待测 |
| s6 问题的模态倾向 | 现有 M·H 或 p_image（注意：若使用训练过的分类器，必须如实写明） | 已有 |

**删除**：U_omni 中的 h_grd（已饱和）；EAB 注意力偏置。

### 3.3 决策规则（两个版本，都要报告）
- **v2-Rule（零训练）**：先决定要不要检索：s1 的置信度低于 τ₁ 才检索。再决定信哪一路：比较各条件的置信度和一致度，取置信度最高、且与至少一个其他条件一致的答案。阈值 τ 在 ≥500 题的校准集上选，**按“相对直接作答的效用差”来选，不按准确率最大值选**。
- **v2-Cal（轻量校准）**：在校准集上用 s1–s6 拟合一个逻辑回归（不到 10 个参数），预测每个动作的正确率，取最大者。论文里如实写成“校准而非训练”，并报告参数量。
- **风险控制（论文的理论卖点）**：用 Learn-then-Test 或 conformal risk control 选阈值，给出“以 1−δ 的概率不差于最强单一动作”的有限样本保证。这一点能把方法和一般的自适应检索区分开，也直接回应审稿人“会不会反而变差”的疑问。

### 3.4 成本
最坏情况下每题需要 1 次 direct prefill 加 |𝒜| 次短解码。报告平均调用次数、输入 token 数和延迟，并和 always-static、SeaKR 对比。可选的省钱版：只有 s1 低于阈值时才去解码证据臂。

### 3.5 EAB 的去向
从方法中移除，改写为分析小节 **“Attention steering moves attention, not answers”**：注意力质量确实被推向支持证据（L1 距离 0.77→0.26），但首 token 的领先幅度大于偏置位移，答案几乎不变。这一节同时解释了 PASTA、FiTM 等注意力干预方法为什么在强模型上增益很小。这是一个有价值的负结果，审稿人通常会认可这类诚实的机制分析。

## 5. 实验协议（论文主表必须遵守）

- **数据与切分**：
  - WebQA：主结果用 distractor 设置（每题自带候选池，数据最全）；开放检索 `webqa_open_*` 作为第二设置。审稿人会问真实网页场景，开放检索能直接回答这个问题。
  - OK-VQA：沿用 omniaware 已有的切分（校准 500 / 开发 256 / 测试 4290）。
  - MMQA、VideoRAG：作为泛化实验，题量按现有资产决定。
- **主指标**：WebQA 用 acc_approx（另报 QA_approx 和 BART），OK-VQA 用官方 VQA accuracy，分图像 / 文本子集报告。
- **基线**（所有臂在同一次运行中同时解码，提示词、预算、候选全部相同）：
  - 单一动作：Direct、Static-Text、Static-Image、Static-Mixed、Rerank-Static
  - 自适应检索：NTE-trigger、SeaKR、原 U 门控（Omni-Aware v1）、UniversalRAG 路由
  - **强基线**：在校准集上选出的最好的单一动作。**主表的相对提升以强基线为分母**，同时也报告相对 static 的数字，满足老师的要求。
  - 上限：逐题选对（oracle）。
- **统计**：按题做配对 bootstrap，给 95% CI；多重比较用 Holm 校正；贪心解码下不报 seed 标准差；同时报告“相对强基线退化”的题比例，用来验证风险控制的保证。
- **预注册**：沿用 omniaware 的 DEV_DECISIONS 机制，开发阶段的决定写入文件并记录 sha256，测试阶段只跑一次。

## 7. 论文改造

### 7.1 定位与标题（候选）
- *When Should a Multimodal LLM Trust the Web? Calibrated Evidence Arbitration for Multimodal Web QA*
- *Omni-Aware: Risk-Controlled Retrieval Arbitration across Modalities*

### 7.2 贡献（新版）
1. **度量**：在 WebQA 和 OK-VQA 上系统地度量检索的作用，发现检索对文本题有益、对图像题有害，逐题选对的上限比任何单一策略高约 27%，而现有的自适应检索信号只能捕捉其中一小部分。同时指出格式和指标伪影会主导多模态 RAG 的评测，给出一套控制格式的评测协议。
2. **方法**：一种零训练（或轻量校准）的逐题仲裁方法，结合不检索时的置信度、跨条件一致度和证据引起的变化，在参数知识、文本证据和图像证据之间做选择，并通过风险控制给出“不差于最强单一策略”的有限样本保证。
3. **机制分析**：说明注意力偏置类方法（包括我们的 EAB）能移动注意力，但不能改变答案，原因是首 token 的领先幅度大于偏置位移。

### 7.3 章节结构
1. 引言：用 N4 的表格（上限差距）和 N5（模态不对称）作为开场的动机图。
2. 相关工作：自适应检索、知识冲突（参数知识 vs 上下文）、多模态 RAG 路由、注意力干预。
3. 度量研究（新）：协议、格式伪影、互补性、模态不对称。
4. 方法：信号、规则、校准、风险控制、成本。
5. 实验：主表（相对强基线和 static）、消融（逐个去掉信号、Rule vs Cal、δ 敏感性）、开放检索、泛化（MMQA、Video）、成本。
6. 分析：EAB 机制、失败案例、格式敏感性。
7. 局限：需要多次解码、阈值依赖校准集、图像证据管线等。

### 7.4 必须删除或改写的旧声明
沿用根因报告 3.3 节的 8 条，最关键的三条：
- 删除“EAB 提升证据利用”作为主要贡献；
- 删除所有以历史缓存基线计算的提升（+33%、+15% 等）；
- WebQA 数字改用官方 acc_approx 报告，注明设置。

### 7.5 预判审稿问题与对策
| 可能的问题 | 对策 |
|---|---|
| 和 Self-RAG / SeaKR / Adaptive-RAG 有什么区别？ | 多模态动作空间；度量出的模态不对称；风险控制保证；零训练；直接与 SeaKR 等同协议对比 |
| 多次解码，成本高吗？ | 报告调用次数和延迟；提供只在不确定时才检索的省钱版 |
