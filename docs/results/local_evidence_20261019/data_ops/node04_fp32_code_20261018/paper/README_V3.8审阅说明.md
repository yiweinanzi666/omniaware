## 二、数据包中的正向结果为什么没有放进论文

数据包按"只列正向比较"整理。但其中多组正向比较，和"EAB 低于 static"出自同一组实验。把同一组实验里有利的臂写进论文、不利的臂删掉，评审读到的就是被裁剪过的实验。所以这些实验要么完整写入，要么整组不写。V3.8 选择整组不写，所以论文里没有出现任何下降的数据。

同一组实验内，EAB 相对 static 的变化（数值都来自数据包本身）：

| 实验 | static | EAB | EAB 增量 |
|---|---|---|---|
| OK-VQA 全 5046 题（BM25，最终 prefill 加偏置） | 32.05 | 31.70 | **−0.35** |
| WebQA T04 门控（train-image128，Combo） | 1.602 | 1.600 | **−0.002** |
| WebQA val-image256 原提示（Combo） | 1.568 | 1.551 | **−0.017** |
| WebQA val-image256 目标绑定提示（Combo） | 2.166 | 2.188 | +0.023 |
| CE 图像确认（Combo，已纳入） | 1.467 | 1.484 | +0.017 |
| T17 文本 128 题 × 12 排列（Combo，V3.7 已有） | 36.11 | 36.16 | +0.045 |

逐项说明：

| 未纳入的实验 | 原因 |
|---|---|
| OK-VQA 5046：触发 +15.7%、门控 +1.1% | 同一组实验里 full 低于 trigger-static。只写触发和门控而不写这一臂，会让读者以为 EAB 在这组实验里也有效。**如果你同意写出全部 5 臂，这组数据其实能强化触发器的结论（+4.35 分，区间 [+3.75, +4.96]），我可以加进去。** |
| WebQA T04 门控、U 缩放 | 门控各行都低于 calce-static；不写 static 那一行，门控行就没有参照。 |
| WebQA-Ctx 路由（train-image128 × 3） | 数据包只给出了路由胜出的几个变体，fixed-native、mass-only、all-modalities 的数值不在包内。只列胜出变体属于挑选对照组。需要完整的路由表才能写入。 |
| DRAGIN-style、Found-in-the-Middle | 包内只有它们相对 raw CE 的提升，没有和 Omni-Aware 的同集比较。按包内数值，在 acc_approx 上 DRAGIN 为 26.8–27.2，route-product 为 25.36；在 Combo 上 FITM 为 1.66，route-product 为 1.44，Omni-Aware 都更低。 |
| 目标绑定提示（+38% / +41%） | 这是输出提示的改动，不属于 Omni-Aware 方法；而且原提示下 EAB 低于 static。 |
| OK-VQA 初答扩展查询与融合（+23.7% / +43.7%） | 这是新方法组件，只在已用过的 train 开发 128 题上测过。可以作为下一版方法的候选，需要在正式集上评测后才能写进论文。 |
| native 输出的 Lexical 提升 | 数据包自己的核查显示，约 74% 的增益来自拒答文本里恰好包含参考词，属于评分伪影。 |

## 五、需要你知道的一点

把上面六组实验放在一起看：在目前所有新跑的本地实验里，EAB 相对 static 的增量都在 −0.35 到 +0.05 之间，区间基本跨零。新数据中的正向收益主要来自触发器（OK-VQA +4.35）和选证校准（Lexical +3.34）。

论文中 EAB 的准确率结论（Table 3：66.15→67.88）仍然来自历史结果，不受这里的影响。但这意味着在当前协议下，EAB 的增益还没有复现出来。投稿前值得考虑：要么查明本地协议与历史协议的差异，要么调整论文对 EAB 准确率贡献的表述，把重点放在已经复现的触发器和校准选证上。
