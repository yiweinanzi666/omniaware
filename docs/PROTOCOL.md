# 实验协议（v2）

论文主表必须遵守本协议。协议对应方向文档第 5 节，并写明切分、主指标、强基线和风险控制的口径。**v2 实验还没有跑。** 下面出现的门槛（例如 +8%）是预注册判据，不是测量结果。

`runs/offline_v2`（命令 `python scripts/analysis/offline_v2.py --seed 20261013 --out runs/offline_v2`）是探索性结果，来自旧管线，含已知 bug，只用于检查代码和信号方向，**不是论文主表**。

## 1. 数据与切分

主结果是 WebQA 与 OK-VQA。MMQA 与 VideoRAG 只作为泛化实验，题量按现有资产决定，不进入主表的分母定义。

| 数据集 | 校准 | 开发 | 测试 | 设置 |
|---|---|---|---|---|
| WebQA（`webqa_full`） | 至少 500 题，取自 **train** | 256 题，取自 **train** | 全部 **4,966** 道 val | **主设置：distractor**（每题自带候选池）。校准不从 validation 抽取 |
| WebQA 开放检索（`webqa_open_*`，当前接口里是 `webqa_open_img`） | 与主设置相同的规则：train 上的校准与开发，彼此不相交 | 同左 | 同一 val 划分下的对应子集 | **第二设置**。审稿人若问真实网页检索，用这一设置回答。当前命令接口只有 S2，没有单独的 S4 |
| OK-VQA（`okvqa`） | 500 | 256 | **val 的剩余部分** | 三者两两不相交。val 为 5,046 题时，测试集为 4,290。测试集为空是错误 |

规则：

- WebQA 的校准集和开发集都来自 train，并且与测试集不相交。删除“WebQA 校准来自 validation”的说法：以前在报告全部 4,966 道 val 的同时把校准说成来自 validation，二者不能同时成立。
- OK-VQA 的校准、开发、测试是 val 上两两不相交的三份切片。测试集是 val 去掉校准和开发之后的剩余部分，不是另一份独立打乱的 val。
- 三个切分两两不相交，由代码断言。测试集为空直接报错。
- 题号列表的 sha256 写入运行输出。测试阶段核对冻结决定文件的 sha256。
- 调参、提示词和阈值都不看测试集。测试集在决定冻结之后只跑一次。在测试集上看过结果再改设置，这一轮只能算开发，不能当作测试。

## 2. 主指标

只用官方评分。

- **OK-VQA**：只报告官方 VQA accuracy。不报告“10 个标注里任一子串命中”的宽松分，也不把宽松分和官方分并列。
- **WebQA**：主指标是 **acc_approx**。同时报告归一化 BART 和 **QA_approx**。图像子集和文本子集都要报告。主结果注明是 distractor（`webqa_full`）还是开放检索（`webqa_open_*`）。不把宽松词面分和 acc_approx 并列。
- 主实验的提示词不要求输出引用行，也不把 `Sources: none` 当作答案。引用评估如果要做，单独运行，不混进主表。

同一运行里所有动作共用**同一个**提示词、解码预算和候选池。答案格式在开发集上选定后冻结：WebQA 输出一句与参考句式一致的完整句；OK-VQA 输出不超过 3 个词，并做 VQA 规范化。格式差异带来的分数变化不算作选择器的贡献。

## 3. 动作、基线与强基线

主方法的动作集合（EAB **不是**其中的臂）：

| 动作 | 含义 |
|---|---|
| `direct` | 不检索 |
| `static_text` | 只用文本证据 |
| `static_image` | 只用图像证据 |
| `static_mixed` | 混合证据，对应以往的 static |
| `rerank_static` | reranker 重排后的 top-k |

对照（与上面的动作在可比的提示词和候选上比较；自适应方法不是“单一动作”）：

- 自适应检索：NTE-trigger、SeaKR、原来的 U 门控（Omni-Aware v1）、UniversalRAG 路由。
- **强基线**：校准集上得分最高的**单一动作**（上表五个动作之一）。身份在测试之前冻结。主表的**相对提升以强基线为分母**。同时报告相对 `static_mixed` 的提升。
- **上限（oracle）**：逐题在这五个动作里取得分最高者。

历史缓存基线作废。根因报告中的 +33%（WebQA）和 +15%（OK-VQA）比的就是这种基线，不能进入主表。+8.43% 和 +14.4% 同样作废。

`gold-in-top-k` 只用于离线分析，**不是**推理时特征，也不能进入 v2-Cal。

## 4. 统计

- 按题做配对 bootstrap，报告 **95% CI**。多重比较用 **Holm** 校正。
- 解码是贪心的。贪心解码下**不报 seed 标准差**。以前把贪心解码的 “3 seeds” 或 ±0.2 当作统计误差，这一做法作废；根因报告指出，±0.2 小于 5,046 题二项分布的标准误（约 0.66 分）。seed 只有在它确实控制了某个随机过程时才报告，并写明它控制的是什么。
- 同时报告“相对强基线退化”的题比例：所选动作的得分低于强基线的题目所占的比例。这个比例用来对照风险控制的声明，它本身不是“方法永不更差”的证明。
- 若门控或选择器的分数仍低于 `direct`，不得写成“优于无检索”。

相对提升的定义：\((\mathrm{方法}-\mathrm{强基线})/\mathrm{强基线}\)。相对 `static_mixed` 用同一个形式，并同时给出绝对差。这些数在跑完之前都是占位符，协议不填任何实测值。

## 5. 预注册

沿用 DEV_DECISIONS 机制。开发阶段的决定写入文件并记录 sha256；测试阶段只读取冻结文件，只跑一次。测试命令是：

```bash
python scripts/v2_runs.py --stage s4 --dataset webqa_full --decisions docs/dev_decisions.json
python scripts/v2_runs.py --stage s4 --dataset okvqa --decisions docs/dev_decisions.json
```

冻结文件至少记录：信号集合、v2-Rule、v2-Cal（7 个参数）、阈值网格、\(\alpha=\delta=0.10\)、效用定义、强基线的身份、答案格式提示词。网格和阈值只在校准集或开发集上决定。**不在测试集上选网格。** 以往 Table 20 的选定点落在测试集网格的最大值上，这一做法作废。

开发集关卡（判据，不是结果）：

- S2 之后，`python scripts/analysis/v2_gate.py --scores <dev-scores.json>` 检查：修管线之后，开发集上逐题选对的上限相对最强单一动作是否仍不低于 **+8%**（相对）。输出 PASS 或 FAIL。
- 进入测试之前，选择器在开发集上相对强基线的提升不低于 **+5%**（相对），配对 bootstrap 的 CI 下界大于 0，并且退化比例不超过 \(\delta\)。不满足就不要把该选择器当作已经通过的测试结果；测试仍然只跑冻结后的那一次，结果好坏都照报。

`<dev-scores.json>` 是 S2 写出的开发集官方分数文件。本文不填写 PASS/FAIL。

## 6. 风险控制的声明

选择器使用**固定序列的 Learn-then-Test**。所选动作的得分低于最强单一动作时，损失为 1。\(\alpha=\delta=0.10\)。

声明是：在校准抽样上，以至少 \(1-\delta\) 的概率，每一个被接受的阈值的真实退化率都不超过 \(\delta\)。

它**不**声明该方法永不更差。在被接受的集合里，用**效用**选择阈值，不按准确率最大值选。效用是所选动作的得分减去最强单一动作的得分。最强单一动作是在**同一个校准样本**上选出的，因此略偏反保守。

v2-Rule 的阈值同样按这个效用来选，不按准确率最大值选。v2-Cal 是校准集上的一个逻辑回归（截距 + 6 个特征，共 7 个参数），论文里写成校准，不写成训练出来的 router。v1 里 `original_retrieve or p_image<0.5` 用过训练过的问题分类器，和“不训练 router”冲突；v2 不使用该分类器。

## 7. 信号（推理时）

每次运行保存：首 token 熵，以及熵除以 \(\log|V|\)；top-1 与 top-2 的 logit 差；贪心序列的 log-prob 和生成长度；每个证据动作相对 `direct` 的首 token 分布 KL；检索器 top-1 分数，以及 top-1 与 top-2 的分差。

v2-Cal 的 6 个系数对应：归一化首 token 熵（熵 \(/\log|V|\)）、logit margin、贪心序列 log-prob、生成长度、上述 KL、检索器 top-1 与 top-2 的分差。未归一化的熵和检索器 top-1 分数一并写入记录，不再各占一个系数。`gold-in-top-k` 不进入这 6 个特征。

## 8. 作废的旧声明

与根因报告第 3.3 节和方向文档第 7.4 节一致，论文里必须删除或改写：

1. “相对 static 提升 X%”作为主结论。主结论改成相对强基线，并另报相对 `static_mixed`。
2. “EAB 提升证据利用 / 位置鲁棒性”。在同协议正结果出现之前，EAB 只作为分析里的负结果：注意力质量被移动，答案不变。
3. WebQA 改用官方 acc_approx，并注明 distractor 或开放检索。不与宽松尺度并列。
4. EAB 的行集合以公式为准：\(a\ge t_{\mathrm{end}}\)（实现名 `ans1`）。把 `ans2` 标成“论文式”的数字要改标。旧门控实际读的是 \(U_{\mathrm{post}}\)，不是正文写的检索时的 \(U\)。
5. WebQA 校准来自 train，并写明至少 500 题、开发 256 题。删除“来自 validation”。
6. 贪心解码不报 seed 标准差，改报配对 bootstrap CI。
7. 选参只在开发集或校准集上进行。测试集网格不能用来挑选报告点。
8. 选择器若仍低于 `direct`，不能声称优于无检索。
