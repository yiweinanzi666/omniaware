dev 网格：
- **EAB 候选（30 个）**：起始行 {ans1（从预测第一个答案 token 的行开始，论文默认）、ans2（decode-only）、q（从问题开始）} × 偏置形式 {pos：γUr，ctr：γU(2r−1)} × **γ ∈ {0.6, 0.9, 1.2, 1.5, 2.0}**。在默认 β、τ_b 下于同一个 base 运行中全部计算。
- **β × τ_b（5 × 3 = 15 个运行）**：β ∈ {0, 0.15, 0.3, 0.5, 1.0}，τ_b ∈ {0.2, 0.4, 0.6}，只跑 phase-1 选出的那一个 EAB 候选。
- **τ ∈ {0.25, 0.35, 0.45}**：没有单独的运行。τ 只决定门控 `retrieve = (u_gate > τ)`，而每个臂对每题都解码，所以门控后的分数可以从所选 (β, τ_b) 的运行中离线精确算出（`paper_analyses tau` 会与运行自身的门控分数核对，不一致即报错）。
- **不确定性设置（3 种）**：sum + 末层（论文）、zsum（两项各自标准化）+ 末层、sum + 中间层。
- **OK-VQA 检索语料（2 种）**：BGE 维基 3M（`okvqa_dense`）、BGE GS-112K 训练语料（`okvqa_gs`，112,724 句）。原先的 BM25 维基（`okvqa`）候选依赖旧主机生成、仓库中没有的输入，无法复现（README 4.2），已在任何 dev 运行之前从候选中移除。`gs168k_full` 含测试题的检索结果，不参加选型，只用于附录。
- 冷启动数据集（WebQA、HybridQA、VideoRAG-Synth）一律使用探测轮（`--probe-uncertainty --first-round-routing`）。
- 缺少任一语料的候选文件时，dev 阶段直接报错，不跳过。

## 规则

选择顺序：语料 → 不确定性设置 → EAB 候选 → β、τ_b → τ。每一步只用前面步骤的结果。

1. **OK-VQA 语料。** 选 static − direct 差值最大的语料。"检索有用"当且仅当这个差值 ≥ 0；否则 OK-VQA 在论文中作为"检索可能有害、门控用来避免伤害"的场景报告，不作为增益来源。
2. **不确定性设置。** 指标是门控分数与直答错误的 Spearman ρ，跨 4 个 dev 数据集（WebQA、OK-VQA-GS、HybridQA、VideoRAG-Synth）取平均；选 ρ 最大的设置。"U 优于 NTE"当且仅当所选设置的平均 ρ 大于下一 token 熵的平均 ρ。
3. **EAB 候选（形式 × γ）只选一种，全局通用。** 指标是同一输入下 EAB 相对 static 的逐题增益：先在每个数据集内取平均，再对数据集取平均（每个数据集权重相同）。选平均增益最大的候选。不允许按数据集分别选择。
   **"EAB 有效"的判据做 30 选 1 的 max-statistic bootstrap 校正**：题目在数据集内分层、各候选共享同一组重采样（配对）；对每个 bootstrap 样本计算各候选的标准化偏差 t*_k = (g*_k − g_k)/se_k，取 M* = max_k t*_k；所选候选的单侧同时下界为 g − q_{0.95}(M*)·se。"EAB 有效"当且仅当该下界大于 0（等价于 p_max-stat < 0.05）。零效应仿真见 `tests/test_dev_select.py`。
4. **β、τ_b。** 在 phase-2 的 15 个运行上，对 phase-1 的 EAB 候选计算按数据集等权的平均增益，选最大者（网格中先出现者优先）。这一步不再做显著性检验：EAB 有效性已由规则 3 判定。
5. **τ。** 在所选 (β, τ_b) 的运行上，离线计算三个 τ 下按数据集等权的平均门控分数，选最大者；并列时取最接近论文值 0.35 的一个。
6. **其余超参数不再调整。** δ = 0.08（路由边际，固定先验，未调参）、k = 5 保持论文值。
7. **最佳候选的乐观偏差。** 所有选择都在 dev 上完成；论文中的数字只来自 test，dev 数字不进正文。β×τ_b 与 τ 在 test 上的扫描只作为**敏感性报告，不参与选择**（paper_runs 的命令注释和 fills 中已标明）。

## v2 预注册

写定日期：**2026-10-13**。选择器实现提交：`9829fefa66b9d80162f1f0535168003123d0347c`（`9829fef`，"Add the v2 arbitration selector and its dev selection step (B3)."）。本节在该提交之后写入，记录的是仲裁代码那一次提交的哈希，不是写入本节的这次提交。

上文的 EAB / β / τ 规则不变。v2 是单独的决定，由 `scripts/analysis/dev_select.py` 的 `select_v2` 机械执行，结果放在决定文件的 `v2` 键下。测试阶段（`--stage test`，或 `frozen_v2`）只读取已经写下的 `decisions["v2"]`，不再搜索网格。这里的 δ = 0.10 是风险控制的水平，不是上文路由边际用的 δ = 0.08。

### 信号集合

选择器只消费已经写好的动作记录，不生成这些记录。每个动作可用的字段是：答案、`answer_empty`、序列 log-prob、生成长度、首 token 的 top-k（id 与 logprob）、熵、`entropy_norm`（熵除以 log|V|）、margin（top1 与 top2 的 logprob 差）、相对 direct 的首 token KL、检索器的 top-1 分数、top-1 与 top-2 之差、`gold_in_topk`。

实际进入决策的只有下面两节写明的量。`retriever.gold_in_topk` 不得作为特征，也不得影响任何决策。检索器的 top-1 与 top-2 之差、以及未归一化的熵，本轮不进入 v2-Cal，也不进入 v2-Rule 的 margin 模式。不使用训练过的模态分类器。

### 两个规则

**v2-Rule（零训练）。** `confidence="margin"` 时，direct 的 margin ≥ τ₁ 视为有信心，选 direct。否则只考虑其余动作：保留那些答案与至少一个不同动作（可以是 direct）的 token F1 ≥ θ 的动作，再取 margin 最高者。token F1 按空白分词的多重集计算，空对空为 1，空对非空为 0。若没有动作达到一致度，退回 direct。`used_evidence` 仅在选中的动作不是 direct 时为真。

`confidence="entropy"` 时，direct 在 `entropy_norm` ≤ τ₁ 时视为有信心（越低越有信心）。一致度规则相同，证据动作按 `entropy_norm` 从低到高排。margin 或熵并列时，按 `direct, static_text, static_image, static_mixed, rerank_static` 的顺序取先出现者。

预注册网格只搜索 margin 这一种信心。entropy 规则已实现，但不在下面的网格里，本次不靠它选阈值。

**v2-Cal（轻量校准）。** 在校准样本上拟合一个所有动作共享的逻辑回归，预测该动作答对的概率，取得分最高者。实现是 numpy 的 IRLS / Newton，不用 sklearn。参数共 7 个：`n_params = 7`，小于 10。`weights[0]` 是截距（`intercept_index = 0`），其余 6 个权重对应下面的特征，每个动作用同一组权重。概率并列时同样按动作顺序取先出现者。拟合时先把特征标准化，再对系数加固定的 L2 惩罚 1e-2，只为了在可分或很小的样本上保持有限；这个惩罚不是第 8 个参数，返回的 7 个权重已经换回原始特征尺度。

六个特征，顺序固定：

1. margin
2. entropy_norm
3. seq_logprob / max(gen_len, 1)
4. kl_to_direct，缺失或 None 记 0
5. 该动作答案与 direct 答案的 token F1；direct 自身记 1
6. 检索器 top-1 分数，缺失记 0

### 阈值网格

从保守到激进，只含 margin 规则。τ₁ 升序：-1e9，0.0，0.25，0.5，1.0，2.0，4.0，1e9。每个 τ₁ 内 θ 降序：1.0，0.5，0.0。共 24 个候选。名称形如 `margin_tau0.25_theta1`。

在常规的有限 margin（大于 -1e9 且小于 1e9）上，τ₁ = -1e9 始终留下 direct，这是最保守的一端；τ₁ = 1e9 总会进入证据动作。θ 越大，一致度越难满足，因此在同一个 τ₁ 里 θ = 1 比 θ = 0 更保守。

### δ、效用与风险控制

δ = 0.10。alpha = δ。效用是阈值要优化的量，定义是 `mean(策略得分 − 最强单一动作得分)`。不按准确率的最大值选阈值。

最强单一动作：各动作平均得分最高者。并列时按上面的动作顺序取先出现者。

Learn-then-Test 风格的固定序列检验（与 `ltt_select` 的文档字符串同一套定义）：

- 损失 L_i = 1，当策略在第 i 题的得分 < 最强单一动作的得分；否则为 0。相等不算退化。
- 原假设 H0：真实退化率 E[L] > alpha，其中 alpha = δ。
- p 值 = P(X ≤ 观测到的退化次数)，X ~ Binomial(n, alpha)。用纯 Python 计算，不用 scipy。当 p 值 ≤ δ 时拒绝 H0，该候选被接受为安全。
- 固定序列：候选已经按保守到激进排好，函数不再排序。按这个顺序走，只要检验拒绝 H0 就接受；遇到第一个不能拒绝 H0 的候选就停止，后面的候选都不再接受。被接受的前缀在固定序列规则下、水平 δ 上是同时有效的。
- 只在被接受的前缀里选择效用最高的候选，不是准确率最高，也不是整个网格上平均分最高的那个。效用并列时取更早（更保守）的候选。
- 若前缀为空，或前缀里的最高效用 < 0，退回 `{"name": "best_single", "action": <最强单一动作>, "fallback": True}`。效用恰好为 0 不退回。

假设，如实陈述：最强单一动作是在同一份校准样本上选出的，因此这个有限样本声明略偏反保守（anti-conservative）。题目按 i.i.d. 处理。这里实现的总体声明是：在校准抽样上，以至少 1−δ 的概率，每一个被接受的候选都满足真实的 P(score_policy < score_best_single) ≤ δ。这弱于「永远不差于最强单一动作」。不声称退化率为 0。

`select_v2(calib_records, delta=0.1)` 只在调用者给出的校准记录上给每个网格候选打分（分数读 `rec["scores"][action]`，须为有限数），再调用上述检验，把选中的候选写入决定字典的 `v2`。它不拆分、也不查看评测题。

### go/no-go

修 bug 之后，在开发集上，逐题选对上限相对最强单一动作 ≥ +8%，才继续把 v2 当作主方法做下去。逐题选对上限是每题在五个动作里取官方得分的最大者。相对提升是 (该上限的平均分 − 最强单一动作的平均分) / 最强单一动作的平均分。这是开发集上的上限判据，不是选择器已经实现的增益，也不在测试集上改规则来凑这个数字。本次提交只登记这条判据，不计算它。
