# WebQA 全库 BGE/CLIP 百分位合并协议 v1

协议身份：`webqa-global-bge-clip-top5-ecdf-v1`。规则在完整全库检索和新 Phase1 答案生成前固定，不通过开发/评价答案选择合并参数。它是对公开语料的修订实现；历史论文的准确语料版本、联合检索和合并代码仍未恢复。

依据：原 EMNLP `sec/04_method.tex` 的 relevance 段提出模态内百分位映射；当前稿 `sec/04_implementation.tex` 的冷启动段由检索器分数选择来源，并复用初始 U。两套编码器的原始余弦不可直接视为同一尺度。本协议具体化未恢复的合并步骤，不把百分位解释成证据正确概率。

1. 使用已冻结的完整公开文本库和全部可用图像，分别作精确内积 top-5 检索。BGE 为文本、CLIP 为真实像素图像；每个问题都查询两库，不读取 Qcate 或支持事实标签进行路由。三个无法解码的原图 ID 及公共修订图像版本继续单独记录，所有问题保留。
2. 校准查询为已冻结的混合训练 500 题。每个编码器恰好贡献 500×5=2,500 个检索分数，同一文档被不同问题检索到时保留各自的 query-document 分数。按模态拟合右连续 ECDF：`r(s)=count(calibration_score <= s)/2500`。不复用旧 caption/BGE 或题内候选 ECDF。
3. 每个新问题将文本五条和图像五条合并，按 `r_j` 降序取总共五条。百分位相同时，先比较模态内原始检索名次，再按 `SHA256("phase1-webqa-dense-ecdf-v1:" + qid + NUL + source_id)` 升序，最后按来源 ID。跨模态不使用原始余弦打破平局，不规定固定图文配额。
4. ECDF 单调不减，平局时保持各库名次优先，因此某库第六条及之后不可能进入联合前五：至少有本库五条排在它之前。每库 top-5 足以执行本规则，不需要额外扩大候选池。
5. 查询、编码器、索引、来源 ID、原始分数、校准池和全部十条候选均保留绑定。新 256 题与校准集无 ID 重叠；模型、来源集合、`r_j` 和最终共同预算供相应 static、replication、decode-only EAB 对照共同使用。

该步骤只产生来源选择及 relevance，不计算初始 U，不重新判断检索触发，也不生成答案。固定来源三臂比较只能给出融合组件收益；整体方法必须另与 Direct、always-retrieve 及适用强基线比较。正式源清单之后仍需按完整提示求共同输入上限，报告每臂实际 token 和成本。

1,024 向量小索引只用于代码接入验证，拟合出的临时 ECDF 保存在 engineering 目录。正式校准必须等待完整编码及索引完成，并与新查询使用相同的两份索引。新结果不用于回改本规则；若后续失败，保留结果后设计单独受控实验。
